# meli-mx-pipeline

**墨西哥 MercadoLibre / MercadoPago 多店铺报表自动化**

用紫鸟（Ziniao）指纹浏览器自动登录墨西哥 MercadoLibre 与 MercadoPago 店铺，
下载全部报表，清洗成结构化数据，再生成带完整勾稽校验的月度财务报表。

全程无人值守：**下载不用点鼠标，报表不用手工拼**。

## 1. 它做什么

```
紫鸟浏览器 ─► 下载原始报表 ─► 清洗成 Parquet ─► 月度财务报表
   12 家店        15 种表单       DuckDB 视图      每店一份 + 全店汇总
```

| 阶段 | 做什么 | 入口 |
|---|---|---|
| **下载** | 4 条路线：Facturación（账单）、Ventas（销售）、Reportes de stock（库存）、MercadoPago（6 种报表） | `run_batch.py` |
| **清洗** | `downloads/mx_sales`（独立子项目）把 xlsx/csv 洗成 Parquet，建 DuckDB 视图 | 跟着下载自动跑 |
| **财报** | 每家店一份 10 张子表的工作簿，另出一份全店汇总 | `run_reports.py` |

一家店一次完整下载约 **15–18 分钟**，12 家店整轮约 **3 小时 10 分**。
财报生成很快：单店 1–15 秒，全店汇总约 30 秒。

**下载和出财报是两件事，分开跑。** 下载是慢的、依赖浏览器的、会失败的；
出财报是快的、纯本地计算、可以随便重跑。想改报表逻辑时不必重新下载。

## 2. 首次安装

### 2.1 必须自己装的两样东西

| 依赖 | 版本 | 说明 |
|---|---|---|
| **紫鸟客户端** | 6.27.1 (V6) | 从紫鸟控制台下载安装 |
| **Python** | 3.11 | 3.8+ 均可，3.11 是验证过的版本 |

> ⚠️ 紫鸟账号必须是**企业登录**（公司名 + 用户名 + 密码），并且在紫鸟控制台里
> **开启 WebDriver 权限**。个人账号无法使用本项目。

可选：装 **LibreOffice** 能让脚本在生成财报后重算一遍公式并检查有没有 `#REF!`
之类的错误。没装也能用 —— 公式照样写进文件，Excel/WPS 打开时会自己算，
只是本次跑不了自动检查，脚本会提示你一声。

### 2.2 装环境

```bat
cd D:\Projects\mx_sales_data

python -m venv .venv
set PYTHONUTF8=1
.venv\Scripts\pip install -r requirements.txt

copy config.example.json config.json
```

**以后更新代码：双击 `update.cmd`**（或 `.venv\Scripts\python -m tools.update`）。它会：月度报表
正在跑或这台机器上改过代码文件时拒绝更新；否则 `git pull` → 装依赖（自动带 `PYTHONUTF8=1`）→
`bootstrap.py` 自检（含 config.json 的店铺配置）→ 所有国家/平台试运行（不打开任何店铺）。
哪一步失败都会说原因，并给出退回更新前代码的那一条命令。`config.json` 和下载的数据不会被动。

> ⚠️ **中文 Windows 上第一次装依赖，先敲一句 `set PYTHONUTF8=1`。** Python 3.11.9
> 自带的那版 pip 会按系统编码（GBK）去读 `requirements.txt`，而这个文件里有中文
> 注释（UTF-8），于是直接报 GBK 解码错误、一个包都装不上（新机器上实测）：
>
> ```bat
> set PYTHONUTF8=1
> .venv\Scripts\pip install -r requirements.txt
> ```

### 2.3 填 config.json

```json
{
  "client_path": null,
  "client_version": "v6",
  "socket_port": 16851,
  "user_info": {
    "company": "公司名",
    "username": "用户名",
    "password": "密码"
  },
  "stores": {
    "default": "BOCINA_TA02",
    "allowed": ["BOCINA_TA02", "UNIT_TA04"],
    "batch": []
  }
}
```

- `client_path`：填 `null` 让程序自动找紫鸟安装位置。
- `allowed`：**白名单** —— 脚本只允许打开这里列出的店铺。
- `batch`：`run_batch.py` 依次跑哪些店；**留空 = 跑 allowed 里的全部**，一般留空即可。
- `no_full`（可选，写在 `stores` 里）：**没有 Full 仓**的店名列表，例如
  `"no_full": ["某店"]`。这些店的库存报表下不到会记成「平台不提供」，不算需要关注。
  页面上分不出"没有 Full"和"库存菜单没渲染出来"，所以这件事只能由人告诉脚本。

> 🔒 白名单是**失败即拒绝**的：`config.json` 格式错误时脚本直接报错退出（退出码 4），
> 而不会退化成"不限制"。账号下能看到 93 家店，误开一家不是小事。

> 🔑 `config.json` 里是**明文密码**，已在 `.gitignore` 里，永远不要提交。
> 如果它曾经出现在截图、聊天记录或旧备份里，去紫鸟控制台改密码。

### 2.4 第一次跑：紫鸟要先下载店铺内核

**在从没运行过紫鸟的机器上，第一次打开某家店会慢很多** —— 紫鸟要先下载该店
的浏览器内核（几百 MB），而店铺的 `webdriver.exe` 就在内核里。脚本会等它，
并打印：

```
    内核 146.1.4.66 尚未就绪，等待紫鸟下载/更新（最多 600 秒）…
      这在从未跑过紫鸟的机器上是正常的，只发生一次。
```

等到了就继续，等不到会给出具体该怎么办。**更稳的做法是装完紫鸟后先手动
打开客户端、进一次店铺**，让它把内核下完，再跑脚本。

> `bootstrap.py` 会报「备用 chromedriver：0 个」的黄色警告 —— **那是正常的**，
> 不要因此去跑 `--drivers` 下载 300 MB。备用驱动只在店铺内核里确实没有
> `webdriver.exe` 时才需要。

### 2.5 自检

```bat
.venv\Scripts\python bootstrap.py
```

看到 `environment OK` 再往下走。它会逐项告诉你缺什么、怎么补。

## 3. 日常使用

### 不想敲命令：双击 `月度报表.cmd`

一个窗口管全部 MercadoLibre 店铺（墨西哥、智利、秘鲁……）：

```
┌ ● 正在运行（定时）：智利（CL），第 2/2 个国家 · 2026-09 · 下载 · AIS_CL（第 3/3 家） · 已运行 3:12:05  [中止这一轮] ┐
├─────────────────────────────────────┬───────────────────────────────────────────────┤
│ [立即运行] [需要人工处理（1）] [每月自动运行] │ 运行日志  [定时]  看哪一轮 [跟随当前运行 ▼] [打开日志文件] │
│  范围  国家 [全部国家 ▼]  月份 [2026-09 ▼]  │ 国家[全部▼] 店铺[全部▼] 级别[全部▼] 查找[___] ☑跟到最新 │
│        ☑ 全部店铺  墨西哥 12 家、智利 3 家  │ 时间      国家   步骤  店铺          级别  内容        │
│  报表输出到 [D:\报表        ][浏览][默认] │ 03:00:01  智利   启动               信息  ━━ 第 2/2 个国家 │
│  运行  [▶ 下载并出报表]  15 家店，约 3.8 小时│ 03:10:44  智利   下载  AIS_CL       警告  ……           │
│        [只下载数据] [只出报表] [补取欠的报表]│                                               │

├─────────────────────────────────────┴───────────────────────────────────────────────┤
│ 报表写到 …                                                   Python：.venv\Scripts\python.exe │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

- **顶上横幅**说现在在跑什么：哪个国家（第几个）、月份、步骤、哪家店（第几家）、跑了多久；
  跑完说结果（全部正常 / 有需要关注的项 / 没跑成）。颜色跟着变。「中止这一轮」也在这里。
- **左边三页**：「立即运行」「需要人工处理」「每月自动运行」。
- **右边**一直是运行日志，任何入口起的那一轮都能看。

以前的 `启动.cmd` 和 `定时设置.cmd` 已经合并进 `月度报表.cmd`，删掉了 —— 桌面上指向它们的
快捷方式要改指 `月度报表.cmd`。已经登记的计划任务不受影响：它们调的是 `run_monthly.cmd`。

**立即运行**：国家默认「全部国家」（一个国家跑完接着跑下一个，每个国家各出一份全店汇总表
和告警文件）；也可以只选一个国家，再取消「全部店铺」挑几家店。**平时点「▶ 下载并出报表」
就够了**，确认框会写明几家店、大约多久。

| 按钮 | 作用 |
|---|---|
| **▶ 下载并出报表** | 下载所选范围 → 接着出报表 |
| **只下载数据** | 只下载并清洗 |
| **只出报表** | 只用已下载的数据出报表，约 1 分钟，可以随便重跑 |
| **补取欠的报表** | 只打开确实欠着报表的店，不重新下载（与店铺选择无关） |
| **先看用哪批数据** | 只读预览：每家店会用哪个下载目录、缺不缺该月账单。任何时候都能点 |
| **中止这一轮**（横幅右边） | 结束正在跑的那一轮 —— 定时任务起的那轮也能停；后面的国家也不跑 |

**窗口里跑的和计划任务是同一个过程。** 按钮起的都是 `run_monthly.py`，唯一的区别是日志里
「入口」那一列写「手动」还是「定时」。锁、日志、告警文件、"硬失败不出报表"两边完全一样。

**关掉窗口不会停。** 那一轮是个独立的后台进程：窗口可以关，它照样跑完；再打开窗口，日志
会自己接上。**有一轮在跑时，运行按钮都是灰的**（不管谁起的）：下载一启动就会重启紫鸟，
再起一轮会把正在跑的那轮杀掉。

> 下载那步如果是硬失败（紫鸟没起来、一家店都没下到数据、白名单或配置读不了），这个国家
> **不会**接着出报表 —— 硬出会拿上一批数据生成一份看起来正常的报表。全部国家时，别的
> 国家照跑。

> **卡住了怎么办。** 运行器卡死（超过 3 分钟没有心跳、但进程还在）时横幅变红，写着
> 「没有响应，多半卡住了」。点「中止这一轮」会把它强行结束。

**报表输出目录**可以直接指向共享盘，记在 `gui_settings.json`（每台机器各自的）。
**每月自动运行也写到这个目录。**

> ⚠ 只选部分店铺时不出汇总表：跑 2 家店也叫 `MX_ML_全店汇总_<月>.xlsx` 的话，会**覆盖掉**
> 真正 12 家店的那份。直接跑 `run_reports.py --stores` 没有这层保护，要自己加 `--no-combined`。

**双击时那个黑框**：只闪一下就关（窗口打开了）。窗口打不开时（缺 `.venv`、缺 tkinter、依赖
没装好），黑框会停住，用一两句话说原因和怎么办，同一段话存在 `logs\_window_check.txt`。
窗口里出了没料到的错会弹一句话，细节记在 `logs\_window_crash.log`。

### 需要人工处理的店铺：看得到、处理完一键补跑

有几类问题脚本自己永远解决不了，必须有人去店铺里点一下：

| 原因 | 窗口里写 | 怎么处理 | 处理完补跑有用吗 |
|---|---|---|---|
| `PAGE_BLOCKED` | 要登录 / 验证 | 打开这家店，按页面提示完成登录或验证 | 有用 |
| `LANGUAGE_WRONG` | 账号语言不对 | 打开这家店，把账号语言改回 Español | 有用 |
| `STORE_OPEN_FAILED` | 店铺打不开 | 确认紫鸟客户端已登录、这家店在紫鸟里能手动打开 | 有用 |
| `NO_PERMISSION` | 缺 MercadoPago 报表权限 | 请账号管理员在 Colaboradores 里开通报表权限 | 开通之前没用 |

**在哪里看到**：

- 窗口的 **「需要人工处理」** 页，标签上写着几家（「需要人工处理（2）」），列出店铺、国家和原因；
  一轮跑完新出现待办时会**弹窗**提醒并翻到这一页。全部国家那一轮里各国的待办都列出来。
- 告警文件 `！报表异常_<YYYYMM>.txt` 的**第一条**就是这件事；运行日志里单独一段，
  级别是「错误」，用「级别：错误」能直接筛出来。

**怎么处理**（都在窗口的「需要人工处理」页里）：

1. 选中店铺（按住 Ctrl 可多选），点 **「打开所选店铺（去登录 / 处理）」** —— 紫鸟会
   逐家打开店铺窗口，在里面完成登录 / 验证。
2. 处理完点 **「处理好了：重跑这些店铺并重出全部报表」** —— 只重新**下载**这几家，
   然后给**全部**店铺重出报表，并重出全店汇总表（别的店用它们最近一批数据）。
   重跑解决不了的（缺权限）会自动跳过并说明。

清单以每家店**最近一次被下载**的那一轮为准：补跑好了的店会自动从清单里消失，
没补跑的不会被漏掉。命令行等价写法：

```bat
.venv\Scripts\python run_monthly.py --stores "UNIT_PW01(catalog)" --reports-for all
```

### 运行日志：窗口右边那一栏

读的是 `logs\runs\` 里的文件。有一轮在跑就自动跟着它；没有在跑的就显示最近一轮。

| 控件 | 作用 |
|---|---|
| 「运行日志」旁的色块 | **这一轮的入口**：手动 / 定时 / 命令行 |
| 看哪一轮 | 默认「跟随当前运行」；下拉可以挑过去任何一轮，每项写着 `日期 时间  入口  （国家）月份  结果` |
| 国家 | 只在全部国家那一轮出现：只看某个国家的行 |
| 店铺 / 级别 | 只看某一家店；全部 / 警告和错误 / 只看错误 |
| 查找 | 在正文和店名里找字 |
| 跟到最新一行 | 勾着时新行出来就滚到底；往上翻看时自动取消，勾上又跟回去 |
| 打开日志文件 | 用记事本之类打开这一轮的完整文件（转发、搜索用） |

窗口里一行分成对齐的几列：时间、（国家）、步骤、店铺、级别、内容；警告整行黄底、错误整行
红底；太长的内容折行，折下来的部分从「内容」那一列开始。

**日志文件里每一行都是固定的六列**，用 ` | ` 隔开：

```
2026-10-13 14:05:01 | 定时 | 下载 | BOCINA_TA02 | 警告 | 没有出现新行……
```

| 列 | 取值 |
|---|---|
| 时间 | `年-月-日 时:分:秒` |
| 入口 | `手动`（「月度报表」窗口点的）/ `定时`（计划任务拉起的，含「现在就跑一次」「试跑一次」）/ `命令行`（直接敲命令或双击 `run_monthly.cmd`） |
| 步骤 | `启动` / `下载` / `补收` / `清洗` / `报表` / `收尾` |
| 店铺 | 店名；不针对某家店的行写 `-` |
| 级别 | `信息` / `警告` / `错误` |
| 正文 | 脚本原来打印的那句话 |

窗口里不显示日期和入口两列（入口就是那个色块），文件内容不变。

**全部国家那一轮**（`--region ALL`）：每个国家一段，段首是一行醒目的
`━━━━ 第 2/3 个国家：智利（CL），3 家店铺 ━━━━`；这一段里每一行的正文前面都带国家代码：

```
2026-10-15 03:10:44 | 定时 | 下载 | AIS_CL | 警告 | [CL]   [警告] 库存报表没有出现新行
```

文件头和最后的总结（每个国家一行结果）不带。只转发中间几行也分得清是哪个国家。

文件开头是一段**文件头**（步骤列都是 `启动`）：入口、运行编号、目标月份、店铺、
步骤、实际执行的每条命令、输出目录、下载时限、机器和用户、Python、代码版本。
转发日志给别人时带上这一段，对方就不用再问"哪台机器、哪个版本、跑的哪条命令"。

**怎么分清是手动跑的还是定时跑的** —— 三处都写着，任看一处：

1. 每一行的第 2 列（所以只转发中间十几行也分得清）
2. 文件名：`logs\runs\20261013_140501_scheduled.log`，结尾是 `manual` / `scheduled` / `cli`
3. 日志栏的色块，以及「看哪一轮」下拉里的每一项

### 每月两条命令

```bat
cd D:\Projects\mx_sales_data

REM 第一步：下载 + 清洗（约 3 小时，跑完可以走开）
.venv\Scripts\python -m platforms.mercadolibre.run_batch

REM 第二步：出上个月的财务报表（约 1 分钟）
.venv\Scripts\python -m platforms.mercadolibre.run_reports
```

`run_reports.py` 默认做**上一个完整月份** —— 当月还没过完，做月报没有意义。

> 这两条是分开调试时用的。想和窗口里跑得**一模一样**，用一条
> `run_monthly.cmd`（见 [3.5](#35-每月定时自动跑)）：它永远给 `run_batch.py` 显式带上
> `--month`，并且有锁、统一日志和告警。直接跑 `run_batch.py` 不带 `--month`
> 走的是"常规路线"（下最近几期账单、销售窗口不按月算、目录不带 `_m` 后缀），
> 和窗口走的不是同一条路。

### 全部命令

**下载相关**

| 命令 | 作用 |
|---|---|
| `run_batch.py` | 全部店铺，下载 + 清洗 |
| `run_batch.py --stores 店名` | 只跑指定的店 |
| `run_batch.py --collect-only` | 只补取上次没拿回来的报表，不重新下载 |
| `run_batch.py --no-transform` | 只下载，不清洗 |
| `run_batch.py --dry-run` | 不开浏览器，只列出会跑哪些店 |

| `run_batch.py --month 2026-07` | 补做某个历史会计月（见下） |
| `run_batch.py --no-full-stores 店名` | 声明这些店没有 Full 仓（等同 `config.json` 的 `stores.no_full`），库存报表缺了不算需要关注 |
| `download_history.py --store 店名` | 拉一家店从开店至今的历史数据 |
| `list_stores.py` | 列出账号下能看到的全部店铺 |
| `open_store.py --store 店名` | 只开一个浏览器窗口，手动操作用 |

**报表相关**

| 命令 | 作用 |
|---|---|

### 补取上次没下完的报表

MercadoPago 有些报表要生成几十分钟甚至几小时。跑完一轮后，没取到的会记在
`logs/pending.json` 里。补取时**不用重新下载**：

```bat
.venv\Scripts\python -m platforms.mercadolibre.run_batch --collect-only
```

在窗口里点「补取欠的报表」是同一件事（等同
`run_monthly.cmd --step collect`，多了锁和统一日志）。

它只会打开确实欠着报表的那几家店。这个登记表存的是"报表行的文字描述"
（类型 + 期间），不是浏览器句柄，所以关店、重启、甚至重启电脑都不影响补取。

### 补做某个历史月份

现在是 9 月，想补一份 7 月的报表：

```bat
REM 第一步：下载 7 月的数据（账单会直接去 7 月那一期的明细页）
.venv\Scripts\python -m platforms.mercadolibre.run_batch --month 2026-07

REM 第二步：出 7 月报表
.venv\Scripts\python -m platforms.mercadolibre.run_reports --month 2026-07
```

`--month` 会做三件事：

1. **账单**改为直接访问 `billing/detail/YYYYMMDD`（该月最后一天）。平台的账单
   首页只摆最近 3 期卡片，更早的账期在页面上点不到，但明细页本身还在。
   进页后会用页面自己写的月份名核对，防止平台把无效日期悄悄重定向到最近一期。
2. **销售窗口**自动放大到覆盖目标月（做 7 月 → 最近 3 个月档）。菜单只有
   2 / 3 / 6 个月三档，超出 6 个月会明确警告。
3. **下载目录**加 `_mYYYYMM` 后缀，例如 `20260914_121653_m202607`。这样出
   8 月报表时不会误选这个只有 7 月账单的目录。
4. **连下目标月之后的 2 期账单**（`--billing-after N` 可调）。订单级费用按
   计费日入账，月末几天的订单佣金常记在下一期 —— 实测 EWTTO_SM 的 7 月订单
   有 56 行费用落在 8/9 月账单里，只下 7 月会少算佣金 973.23，代扣税等额虚高
   （9.221% vs 正确的 9.172%）。

出报表时 `--month` 按三层优先级给每家店挑目录，**每一层都会把选择理由写在屏幕上**：

1. **含该月账单的目录** —— 最好，收入和费用都齐
2. **账单没有、但销售数据盖得住该月的目录** —— 退而求其次。说明会写明
   「⚠ 无 2025-12 账单，但销售数据含更早的订单，盖得住该月：收入可用，
   平台费用会缺失，代扣税率会失真」
3. **都没有** —— 退回最新目录，并写明「收入和费用都会缺失，仅供参考」

第 2 层的判据是**证据**不是推测：只有当销售文件里确实存在**早于目标月月初**的
订单，才认定窗口盖过了这个月。反过来不成立（没有更早的订单也可能只是这家店
当月才开张），所以这个判断只用来肯定、不用来否定。

⚠ 无论走到第几层，报表里的【本期账单已下载】校验都会直接点名缺了哪个月、
目录里实际有哪几个月 —— 不会让人从「代扣税率 19.4%」这种症状去倒推病因。

> ⚠️ **不下 `--month` 的数据直接出历史月报表，数字是错的。** 最新目录只有最近
> 两期账单，用它做 7 月报表时佣金几乎为 0，代扣税会被算成佣金的三倍
> （实测 28.6%，正常 9.05%）。

**历史月份拿不到的东西**（平台限制，不是代码问题）：

| 数据 | 情况 |
|---|---|
| ⑨ 库存与动销 | 库存报表**只有当前快照**，没有历史。做 7 月报表时这一页反映的是今天的库存 |
| MercadoPago 流水 | 60 天滚动窗口，再早就取不到，相关校验会标「跳过」 |
| ⑥ 退货质检 | 按质检日的滚动窗口，早期记录取不到 |
| 各期报表张数 | 每个账期平台给的报表数不同（8 月 4 张，7 月 3 张，少 `Cargos_Full`），少的那张对应的校验会标「跳过」 |

② 损益表、③ 五座桥、④ 费用明细、⑦ SKU 盈利**不受影响** —— 它们只要 Ventas
和账单，这两样都能按月拿到。

### 3.5 每月定时自动跑

`run_monthly.py` 是**唯一的运行器**：「月度报表」窗口、计划任务、命令行，跑的都是它。
文件名还叫 monthly，只是因为已经登记的计划任务调的是 `run_monthly.cmd`，改名会让
它们全部失效。

```
run_monthly.cmd                      # 上个月，下载 + 出报表
run_monthly.cmd --month 2026-07      # 补做某个月
run_monthly.cmd --step report        # 只重出报表，不重新下载
run_monthly.cmd --step download      # 只下载
run_monthly.cmd --step collect       # 只补取欠着的报表
run_monthly.cmd --stores A B         # 只跑这几家（不出全店汇总）
run_monthly.cmd --region ALL         # 全部国家依次跑（墨西哥第一）
run_monthly.cmd --dry-run            # 只打印会执行什么
```

| 参数 | 作用 |
|---|---|
| `--month YYYY-MM` | 目标月份，默认上个月 |
| `--step both\|download\|report\|collect` | 只跑其中一步，默认 `both` |
| `--stores 店名 …` | 只跑这几家；给了就**不出全店汇总表** |
| `--region MX\|CL\|PE\|ALL` | 哪个国家，默认 MX；`ALL` = 全部国家依次跑（见 [3.6](#36-多国家区域)） |
| `--out-dir 目录` | 报表输出目录。不给就用窗口里选的，再没有才用默认目录 |
| `--entrance manual\|scheduled\|cli` | 谁起的这一轮，**只影响日志里「入口」那一列**。窗口和计划任务各自带上；手敲命令不用写，默认 `cli`（命令行） |
| `--max-hours N` | 下载这一步最多跑 N 小时，默认 5，`0` = 不限。见下 |
| `--dry-run` | 只打印会执行什么 |

三个入口的差别只有 `--entrance` 这一个参数：

| 入口 | 实际执行 | 日志里写 |
|---|---|---|
| `月度报表.cmd` 窗口里点按钮 | `run_monthly.py --entrance manual --region … …` | 手动 |
| 窗口「每月自动运行」页登记的计划任务 | `run_monthly.cmd --entrance scheduled --region ALL` | 定时 |
| 手敲命令 / 双击 `run_monthly.cmd` | `run_monthly.py` | 命令行 |

双击 `run_monthly.cmd`（不带参数）时，黑框里打的是短行（`14:05:01  下载  BOCINA_SM  [警告]  …`），
跑完写一句结果并停住等你按键（10 分钟后自动关）；计划任务带着参数调它，**从不停住**。

**每跑一轮写一组文件**，文件名是「开始时间 + 入口」：

```
logs\runs\20261013_140501_scheduled.log     给人看的日志（固定六列，见上一节）
logs\runs\20261013_140501_scheduled.json    摘要：每一步的退出码和用时、告警内容、实际命令
logs\current.json                            正在跑的那一轮；跑完即删
```

旧版的 `logs\monthly_<YYYYMM>.log` / `.json` 不再写了（已有的旧文件不受影响）。
同一个月跑几轮也不会互相覆盖。

**下载有自己的时限（`--max-hours`，默认 5 小时）。** 到点就掐断下载（连同它起的
紫鸟和浏览器），**报表照样按已经下到的数据出、告警照样写**，最后以退出码 7 结束。
以前只有计划任务那个"超时自动停止"，它杀的是整条链 —— 报表不出、告警不写，
第二天什么痕迹都没有。

**防重入。** 同一时间只允许一轮（`logs\monthly.lock`）。手动点和定时任务撞上时，
后来的那一轮直接跳过（退出码 5），日志里写明"另一轮还在跑"。

**定在每月 15 号**：上个月的账单那时候已经闭账，数字基本稳定。跑当月没有意义
（账期没结束），所以这个脚本默认目标就是上个月。

**登记计划任务：双击 `月度报表.cmd`，翻到「每月自动运行」页**

推荐**一个任务跑全部国家**：`月度报表`，参数 `--entrance scheduled --region ALL`。选每月几号
几点 → 点「设为每月自动运行」。墨西哥、智利……一个国家跑完接着跑下一个，同一份日志；不会再有
"两个国家的任务时间挨得近、后一个撞上锁被跳过（退出码 5）"的问题。

它生成完整的任务 XML 再导入，下面这些**命令行没有开关、只能在任务计划程序里手点**的设置一次配好：

- 只在用户登录时运行（`InteractiveToken`）
- 如果错过计划的开始时间，立即启动任务（`StartWhenAvailable`）
- 运行超过 N 小时自动停止：**每个国家 6 小时**（2 个国家 = 12 小时）。只是兜底：运行器自己
  在每个国家下载满 5 小时就掐断并接着出报表。以后加了国家，页面会提醒重新点一次「设为每月自动运行」
- 关掉电池相关的两项限制
- 上一轮没跑完就忽略新的触发（叠在 `run_monthly.py` 自己的锁文件之上）

**以前按国家登记的旧任务**（生产机器上的 `MX月度报表`，可能还有 `CL月度报表`）：

- 页面下方「按国家登记的旧任务」列出它们的时间和上次结果。**程序不会自己删。**
- 点「设为每月自动运行」时如果旧任务还在，会问你：「是」= 登记新任务并删除旧任务（推荐）/
  「否」= 只登记新任务 / 「取消」。
- 新旧都在时状态区是红字：那个国家每月会被跑两次。也可以点旧任务旁边的「删除」。
- 只想先不动：旧任务照样能跑，状态区黄字提示可以换。

| 按钮 | 作用 |
|---|---|
| **试跑一次（1 分钟）** | 建一个临时任务只跑「出报表」（全部国家），跑完自动删。验证能不能被计划程序拉起、工作目录对不对、中文乱不乱码、日志落没落盘 |
| **现在就跑一次** | 不等到 15 号，现在就按正式任务跑一遍。窗口可以关，不影响它继续跑 |
| **取消每月自动运行** | 撤掉 `月度报表`，程序和数据都不动 |
| **检查这台电脑** | 只读检查睡眠、自动登录、锁屏、虚拟环境、店铺清单；电源那几项可以一键修（会弹管理员确认） |
| **打开日志文件夹** | 打开 `logs\runs\`。平时不用开 —— 右边的「运行日志」里就能看、能挑 |

要敲命令也行：

```
schtasks /create /tn "月度报表" /sc MONTHLY /d 15 /st 02:00 /it ^
  /tr "\"D:\Projects\mx_sales_data\run_monthly.cmd\" --entrance scheduled --region ALL"
```

但这样建出来的任务**缺上面那几项设置**（超时默认 72 小时、错过不补跑），得再去 `taskschd.msc` 里补勾。

> ⚠️ **`/IT`（只在用户登录时运行）不能省。** 紫鸟是带界面的 Electron 程序，
> 「不管用户是否登录都要运行」那个选项会把任务丢进 session 0，没有交互桌面，
> 浏览器根本起不来。

跑这个任务的机器还要满足（「检查这台电脑」会逐条告诉你过没过）：

- 自动登录并保持登录态，关掉锁屏和屏保
- 永不睡眠：`powercfg /change standby-timeout-ac 0`

凌晨跑还有个好处：跑批会重启紫鸟客户端，那个点不会关掉任何人开着的窗口。

**什么时候会收到告警**：报表里**会缺数据**、或者**报表根本没生成**时，才会在报表
输出目录写一个 `！报表异常_<YYYYMM>.txt`。**手动跑的和定时跑的一样写**，文件里
写明这一轮是哪个入口起的、完整日志在哪。具体是这几种：

- 下载硬失败（紫鸟出错、一家店都没下到、白名单 / 配置问题）—— 报表没出
- 有店铺没下到数据、有店铺部分报表没下成 —— 逐条列出店名，并按原因码统计缺了
  几张（原因码见 [第 9 节](#没下到的报表为什么没下到)）
- 下载超过时限被掐断
- 至少一份报表没写出来
- 运行器自己出错

只是**平台还没把报表生成好**（原因是 `STILL_GENERATING` / `PLATFORM_DELAYED`，
MercadoPago 的报表经常当晚生成不完）**不告警**：这是常态，日志和运行摘要里会写
「还欠 N 张报表，平台还在生成」，过几个小时点「补取欠的报表」即可。

报表生成了但有校验没过（报表步骤退出码 1）也**不告警** —— 桥B 每家店每个月都
不过，那样每月都报一次，两个月后就没人看了。校验结果本来就在报表的
【⑩ 数据缺口与待办】里。只是清洗有文件没过、被人点了中止、因为另一轮在跑而
跳过，也都不告警。

在 `config.json` 里加 `"monthly": {"webhook": "..."}` 可以让告警同时推到企业微信
机器人。

> ⚠️ **财务手填的单位采购成本，每次出报表都会重置。** 同一个月别反复重出报表覆盖
> 财务已经填好的那份 —— 要重出就先改 `--out-dir` 指到别处。

### 3.6 多国家（区域）

同一个紫鸟账号下有墨西哥（MX）、智利（CL）、秘鲁（PE）的店。所有国家共用一个紫鸟客户端，
锁是全局的：**同一时间只有一轮**。一轮可以是一个国家，也可以是 `--region ALL`（全部国家
依次跑）。

**config.json**：`allowed` 里是两国全部店铺；`batch` 仍是墨西哥那一批；智利的店在
`regions` 里标出来，智利那一批写在 `batches.CL`。没写进 `regions` 的店一律算墨西哥，
所以旧配置一个字不改照样能跑。

```json
"stores": {
  "default": "BOCINA_SM",
  "allowed": ["BOCINA_SM", "Tecnohub_CL (个人店)"],
  "batch":   ["BOCINA_SM"],
  "regions": {"Tecnohub_CL (个人店)": "CL"},
  "batches": {"CL": ["Tecnohub_CL (个人店)"]}
}
```

**命令行**：`run_monthly.py` 有 `--region MX|CL|PE|ALL`，`run_reports.py` 有 `--region MX|CL|PE`，默认 MX。

```
python run_monthly.py --region CL                 # 智利，上个月，下载 + 出报表
python run_monthly.py --region CL --step report   # 只重出智利的报表
python run_monthly.py --region ALL                # 全部国家，一个接一个
python run_monthly.py --region ALL --dry-run      # 看看每个国家会执行哪些命令
python -m platforms.mercadolibre.run_reports --region CL --dry-run
```

**全部国家（`--region ALL`）**：

* 顺序是墨西哥第一，然后是 config 里有店的其他国家；一家店都没有的国家跳过，日志里记一笔。
* 每个国家的子进程命令和单独跑它时**一字不差**（墨西哥的仍然不带 `--region`、不带店铺），
  各出各的全店汇总表、各写各的告警文件。
* 一个进程、一把锁、**一份**运行日志：每个国家一段，段内每行带 `[MX]` / `[CL]`（见
  [运行日志](#运行日志窗口右边那一栏)）。
* 一个国家下载硬失败或配置有问题，只影响它自己（记下、告警），接着跑下一个；有人点了中止，
  整轮停下，后面的国家不跑（退出码 6）。
* 退出码取最坏的那个国家：0 < 1 < 7 < 2 < 3 < 4。
* 不能和 `--stores` 一起用（退出码 3）—— 店铺子集只在一个国家里有意义。
* 下载时限 `--max-hours` 每个国家各算各的。

* 墨西哥：子进程命令、文件名和以前**完全一样**。
* 智利：运行器给 `run_batch.py` **永远**显式传智利的店铺清单（`run_batch` 不带店铺时
  走的是墨西哥那一批），给 `run_reports.py` 传 `--region CL`。
* `--stores` 里有不属于这个国家的店：退出码 3，什么都不跑。

**文件名**（都在同一个报表输出目录里；全部国家那一轮也一样，每个国家各一份）：

| | 墨西哥 | 智利（秘鲁同理，换成 PE） |
|---|---|---|
| 全店汇总 | `MX_ML_全店汇总_<月>.xlsx` | `CL_ML_全店汇总_<月>.xlsx` |
| 单店报表 | `<店名>_<月>.xlsx` | 同左 |
| 告警文件 | `！报表异常_<年月>.txt` | `！报表异常_CL_<年月>.txt` |

日志开头有一行「区域：智利（CL）」，运行摘要 JSON 里有 `"region"`（全部国家那一轮是 `"ALL"`，

**计划任务**：推荐一个 `月度报表`（`--region ALL`），见 [3.5](#35-每月定时自动跑)。以前按国家

**清洗目前只支持墨西哥**：`downloads/mx_sales` 读的是 "Ventas MX" 表。一批全是智利店时
`run_batch.py` 打一行「清洗目前只支持墨西哥，其他国家的店铺跳过这一步；不影响报表」，批次
汇总里记 `"transform": {"skipped": true, "reason": "region"}` —— 不算失败，报表读的是
原始导出。

**店名要和紫鸟里一字不差**：智利那家店在紫鸟里叫 `Tecnohub_CL (个人店)`，不是
`Tecnohub_CL`。写错了这家店会被当成"不在白名单"跳过。

### 3.7 多平台：Falabella（智利）

除了美客多，现在还有 **Falabella 智利**。一家店属于一个"市场"：平台 + 国家，写成
`ML-MX`（美客多墨西哥）、`FA-CL`（Falabella 智利）。代码和文件名规则见
`docs/REPORT_FAMILY.md` 第 1 节。

**config.json**：用 `catalog` 写明每家店的平台和国家，`batches` 按市场写。**一旦写了
`catalog`，白名单里每家店都要在里面**（漏写的店会报错，不会被当成墨西哥）。旧写法照样能用。

"stores": {

```

**怎么跑**：和美客多完全一样，同一个窗口、同一个计划任务。

* 窗口「国家」下拉框里多一项「Falabella 智利」（只有 config 里有 Falabella 店时才出现）。
* 「全部国家」/ 计划任务 `月度报表`（`--region ALL`）：美客多的国家先跑（顺序和以前一样），
  然后跑 Falabella 智利。
* 命令行：`run_monthly.py --region FA-CL`（只跑 Falabella 智利），其余参数（`--step`、
  `--stores`、`--month`）照旧。

```
python run_monthly.py --region FA-CL                  # Falabella 智利，上个月，下载 + 出报表
python run_monthly.py --region FA-CL --step report    # 只重出报表

**文件名**：单店 `<店名>_<月>.xlsx`，全店汇总 `CL_FA_全店汇总_<月>.xlsx`，告警

**和美客多报表的区别**（十张子表、排列和读法都一样）：

| | 美客多智利 | Falabella 智利 |

### 3.9 SKU 成本表：让报表算出商品成本和毛利

平台数据里没有进货成本，所以报表默认只到"经营贡献毛利"。财务填一张**所有平台共用**的成本表后，
美客多（墨西哥、智利、秘鲁）、Falabella、亚马逊的报表会自动算出商品成本和税前利润。
美客多按⑦表五的“销售件数”计成本：本月订单的件数，不含发货前取消的、和平台质检判定可再售已回库的退货。

1. 生成模板（列出最近一次下载里出现过的全部 SKU，只读文件、不打开店铺）：
   `.venv\Scripts\python -m tools.sku_cost_template --out sku_costs.xlsx --month 2026-09`
2. 在 `sku_costs.xlsx` 里填 `单位成本`（到岸成本：进价＋运费＋关税，每件）和 `币种`（与报表币种一致，
   不做汇率换算）。涨价时**加一行**并填 `生效日期`，不要改旧行。`平台`/`国家` 留空 = 所有平台/国家通用。
   再次运行第 1 步会保留已填的成本，只补新 SKU。
3. 在 `config.json` 加一段：`"reports": {"sku_costs": "sku_costs.xlsx"}`，然后重出报表
   （`--step report`）。

没填成本的 SKU 不算成本，② 页会写明覆盖了多少销售额，⑩ 页列出缺成本的 SKU。成本表是业务数据，
不进 git。`bootstrap.py` 会检查配置的成本表能不能读。

## 4. 财务报表：十张子表

每家店一个 `.xlsx`，十张子表。**从左到右是一条推理链**：先给结论，再证明结论，
最后列出还欠什么。

| 子表 | 回答什么问题 |
|---|---|
| **① 阅读说明** | 这份报表怎么读、数据从哪来、哪些是估算 |
| **② 合并损益表** | 从 GMV 一路推到税前净利润。行位置固定，可跨月对比 |
| **③ 平账勾稽表** | 五座桥：A 订单资金流、B 月度账单、C 两种口径对比、D 从到账净额到经营利润、E 代扣税解释。**"平不了账"的时候看这一页** |
| **④ 平台费用明细** | 本期账单全部费用科目（西班牙语原文 + 中文），标明结算通道；末尾附**与 ② 的对账**，逐项拆开两页费用合计为什么不相等 |
| **⑤ 退货退款分析** | 按订单状态、按金额、按平台/卖家责任划分 |
| **⑥ 退货质检明细** | Full 仓逐件质检结果与退货原因，含可回收 / 彻底损失判定（秘鲁没有 Full：本页只写"不适用"） |
| **⑦ SKU 盈利分析** | 五张表（见下），**要看某个 SKU 到底赚不赚钱，直接看表五** |
| **⑧ 月度趋势** | 销售报表窗口内各月的销售、三项费率、退货率走势 |
| **⑨ 库存与动销分析** | Full 仓库存结构、周转、断货与积压，并把平台的近 30 天销量与销售报表逐 SKU 核对（秘鲁同上：不适用） |
| **⑩ 数据缺口与待办** | 本期校验结果、数据缺失项、需要人处理的事 |

### ⑦ SKU 盈利分析的五张表

异常订单的**库存后果完全不同**，混在一起算 SKU 盈利必然是错的，所以拆开：

| 表 | 内容 | 采购成本 |
|---|---|---|
| **表一** | 按 SKU 汇总**正常订单** | 自动引用表五 |
| **表二** | 取消订单明细（从未发货，库存没动） | 恒为 0 |
| **表三** | 退货可回收明细（已质检判定可再售） | 恒为 0 |
| **表四** | 其他异常明细（不可再售 / 仲裁 / 投诉 / 换货 / 尚未质检） | 自动引用表五 |
| **表五** | **SKU 真实盈利（最终口径）** = 正常订单 ＋ 表四 | ★ 唯一录入位 |

表五的逻辑：取消和可再售的货**还在手上、还能再卖**，摊到 SKU 上会凭空压低盈利；
表四那批货**已经确定收不回来**，货值实实在在损失了，必须算进该 SKU 的成本。

五张表**列完全对齐**（30 列），同一列永远是同一个项目，可以直接从表一拖到任意
一张明细上求和。明细独有的项（订单号、质检结论等）放在 Q 列之后。

> ★ **你唯一要手工填的东西**：表五黄色的「单位采购成本」列（到岸成本，含头程运费
> 与关税）。填一次，表一、表四、⑨ 库存页的库存金额、② 损益表的税前净利润全部
> 自动算出来。平台所有报表都不含进货成本，这是唯一的缺口。

## 5. 口径：几个必须先知道的约定

这几条是踩了很多坑才定下来的，不了解会看错数。

### 5.1 损益表按订单日，账单费用按计费日

收入与订单级费用按**下单日**归集；广告费、仓储费这类月度账单费用按**计费日**归集。
两种口径的对比在 ③ 平账勾稽表的桥 C。

### 5.2 代扣代缴税金是算出来的，不是平台给的

平台在销售报表里只给**合并值** `Cargo por venta e impuestos`（佣金 ＋ 代扣税），
账单明细里只给**纯佣金** `Cargo por venta`，代扣税从来没有独立科目。所以：

```
代扣代缴税金 = 销售报表的「佣金及税金」 − 账单的纯佣金
```

实测各店稳定在 GMV 的 **9.05%** 左右（法定名义值）。落在 8.5%–9.5% 之外会被校验拦下。

### 5.3 佣金与代扣税在 ⑦⑧ 页按订单拆开

同一套逻辑逐单还原：账单佣金按订单号挂回每一单，代扣税 = 合并值 − 纯佣金。
账单尚未出的订单按店内实际佣金率推算，并保证两列之和仍等于损益表 —— **12 家店
逐月验证，合计全部守恒**。

⑧ 月度趋势里，账单只覆盖最近两三个计费期，更早的月份**推代扣税而不是推佣金**：
代扣税是法定比例（逐月几乎不动），佣金率却随品类在 11%–17% 之间跳，推佣金等于编数字。
每行末列注明这一行是"账单实测"还是"按规律推算"。

### 5.4 ⑨ 库存页是快照，不能和损益表相加

库存报表是**下载当时的快照**（不是月末余额），它的"近 30 天"也以快照日为终点，
与会计月不重合。这一页只用来看库存结构和动销，不参与损益。

销量核对的自算口径是**剔除异常订单后的全部销量** —— 实测过四种口径，这个最贴平台：
603 个 SKU 里 563 个差不超过 1 件。容差设为 2 件或 5%（平台只给到快照那一刻，
我们只能按整天切窗口）。

积压线取 **120 天**而不是 90：120 天正是 Full 开始按「库龄 4 个月以上」加收长龄费
那条线，越过它积压才真的开始花钱。补货线 14 天。「整批在途尚未入仓」归为正常，
否则每批新到货都会进待办清单把真问题淹掉。

### 5.5 部分退款订单，销售报表会重复扣一次佣金

平台对部分退款的订单按退款比例 `p` 同时退还佣金与代扣税，但销售报表的
「退款与取消」列写的是 `应退 ＋ 原佣金`：

```
应退      = p × (GMV − 佣金 − 代扣税)
销售报表写 = 应退 + 原佣金        ← 多扣了一个原佣金
```

已用 MercadoPago 现金流水做过带对照组的验证：正常订单 3,175 笔里 93%–97% 的
Total 与实际到账差 ≤0.02，而部分冲销的单**每一笔**都正好差一个原佣金。

修正只加在**推导利润**的那条链上：② 损益表的「加：部分退款重复扣佣金调整」行、
③ 桥D 的 D1b、以及内部的 `ctx["contrib"]`（这三处算的是同一个数，改一处不会报错，
必须同动）。逐单明细在 ⑩ 页 3.3，并标明每一单是「现金凭证确认」还是「按规律推定」。

⚠ **桥A 刻意不加。** 它是把销售报表各列重新加一遍去对它自己的 Total 列，验的是
「我们有没有读懂这个文件」，不是「这个文件对不对」。加上去残差会从 0.00 变成
−1,020.41，毁掉一个目前唯一能证明解析正确的检查。桥B（纯账单侧）、桥C（比费用列
不是退款列）、桥E（讲代扣税）同样不涉及。

⑤ 退货退款分析与 ⑦ SKU 盈利分析**只加说明文字、不改数字** —— 这两页要与销售报表
原始数据一一对应，改了数就对不上了。页面上会写明虚高/低估的金额并指向 ② 和 ⑩。

### 5.6 ② 与 ④ 的费用合计本来就不相等

② 按【订单日】归集订单级费用、佣金取毛额、配送费取自销售报表；④ 按【计费日】
列出账单原始行。差异全部来自这两点，④ 页末尾的对账块逐项拆开，残差为 0。

⚠ **冲销行不只在贷记单文件里。** 账单文件 `Reporte_Facturacion` 自己也带着
`Anulación...` 行 —— BOCINA_TA02 2026-08 共 46 行冲销，只有 17 行在贷记单文件，
其余 29 行在账单文件内。拿贷记单文件的合计当作"本期全部退还"去倒推差额，
会得到一个对应不上任何东西的余数。

### 5.7 组合订单与换货单会被拆开

销售报表把一单多件写成：母行带走全部金额却没有 SKU，紧随其后的 N 行有 SKU
没有金额，父子之间**没有任何共同 ID**，只能靠相邻位置关联。⑦ 页按
`件数 × 单价` 把母行金额精确拆到各子 SKU（实测分毫不差）。换货单更可靠些 ——
两行共享同一个 `# de venta`。

**只有 ⑦ 页用拆分后的数据**；损益表、各座桥、全部校验仍读原始明细，这样既拿到
按 SKU 的归属，又不会扰动已经通过的勾稽。

## 6. 校验：十二条硬检查

每次生成报表都会跑，结果印在控制台并写进 ⑩ 页。

| 校验 | 不通过意味着 |
|---|---|
| 本期账单已下载 | 这个下载目录里没有该会计月的账单 —— 平台费用、佣金、代扣税全部缺失。**其余几条异常多半是它的连带结果**，先修这条 |
| 销售数据覆盖整个会计月 | 销售报表是滚动窗口，窗口起点晚于月初就说明这个月被截断了。判断依据是下载时**实际请求的窗口**（记在 `run_meta.json`），不是最早一笔订单的日期 —— 后者晚于月初也可能只是这家店当月才开张 |
| 桥A 逐笔订单勾稽 | 销售报表内部对不上，还有未识别的隐藏费用或折扣 |
| 桥B 账单应付 vs 实际扣款 | 账单口径与实际扣款差异 —— **常见原因是账单期数不够，多拉一期通常就平了** |
| 费用科目全部已登记 | 出现了 `FEE_CATALOG` 里没有的科目，需人工确认归属 |
| 账单费用小计自平 | 兜底行不为零，有科目落在非预期位置 |
| 代扣税率在预期区间 | 实测税率越出 8.5%–9.5%，税制或账号税务状态可能变了 |
| Full 费用报表 vs 账单 | 两者必须相等，相加即重复计数 |
| MercadoPago 流水交叉验证 | 第三方凭证与销售报表对不上 |
| 账单有费用但销售报表无此单 | 平台为一笔销售报表上不存在的订单收了钱 |
| 取消单的费用是否已冲销 | 已取消却计了费且没冲销（发货前取消平台通常不计费，只统计确实计过的） |
| 部分退款订单重复扣佣金 | 见 5.5，已在损益表修正，此处只作提示 |

**未登记的科目永远单列，绝不悄悄并进"其他"。** 金额照常计入以保证勾稽，
但会在 ⑩ 页要求人工确认 —— 一个看不见的兜底项比一个显眼的缺口危险得多。

## 8. 新人最容易踩的坑

### ① 目录不对

- `run_batch.py` / `run_reports.py` → 在**项目根目录**跑
- `python -m mx_sales ...` → 在 **`downloads/` 目录**跑

### ② Python 用错了

机器上可能同时装着别的 Python（conda 的 `(base)` 之类）。直接敲 `python`
会用到哪个说不准，而**不同环境的库版本不同**。永远写全路径：

```bat
.venv\Scripts\python ...          在根目录
..\.venv\Scripts\python ...       在 downloads/ 目录
```

这不是洁癖。`requirements.txt` 锁的是 **pandas 3.0.5**，而 conda 环境里常见的是
pandas 2.x —— 两者对 `astype(str)` 遇到 NaN 的处理**不一样**（2.x 转成字面量
`"nan"`，3.x 保留 NaN）。曾经因为在 pandas 2 上开发、在 pandas 3 上运行，
⑨ 库存页直接崩在 `int(NaN)` 上。

现在两个版本的输出已做过**逐单元格比对，13 份报表差异为 0**，但前提是用
`.venv` 里的解释器。验收新机器时也必须用它。

### ③ `allowed` 是"权限清单"，不是"任务清单"

往 `allowed` 里加两家店，**不会**让 `run_downloads.py` 下载两家 —— 那个脚本
设计上只跑一家。要下多家请用 `run_batch.py`。

### ④ `run_downloads.py` 不做清洗、不出报表

它是单店调试工具。要端到端出结果，用 `run_batch.py --stores 店名`。

### ⑤ 报表被 Excel 占用会写入失败

生成时如果同名文件正在 Excel 里开着，**会失败**，脚本会明确报「写入失败」
并保留磁盘上的旧文件（不会假装成功）。跑之前先把
`downloads/data/reports/financial/` 下的工作簿都关掉。

如果你正开着某份报表又重跑了，那一份会保持旧版 —— 关掉后单独重跑那一家即可。

### ⑥ 定时任务不能用"不登录也运行"

紫鸟是带界面的 Electron 程序，需要真实桌面。Windows 计划任务必须选
**"只在用户登录时运行"**，并且那台机器要保持登录、不休眠。

### ⑦ `run_report.py` 和 `run_reports.py` 不是一回事

- `run_report.py`（单数）：往每个下载目录写 `REPORT.md`，由下载流程调用，你不会直接跑它
- `run_reports.py`（复数）：**月度财务报表入口**，你要跑的是这个

## 9. 看懂运行结果

### 下载跑完

```
  店铺               状态           文件数  备注
  清货2_EE02         ok               19
  EWTTO_SM         partial          14  1 处错误：...
  NARWAL_EE01      partial          17  1 张仍欠
  UNIT_TA04        ok               17  1 张无流水
```

| 状态 | 含义 |
|---|---|
| `ok` | 正常：没有路线出错，应下的报表都在（平台本来就不提供 / 该区间没数据的不算缺） |
| `partial` | 下到了文件，但有路线出错，**或者应下的报表不全（包括还欠着的）** —— **要看一眼** |
| `failed` | 这家店整个没跑起来 |
| `not-allowed` | 不在白名单里 |

> 以前只有路线报错才算 `partial`，一家店还欠着报表、甚至账单一张都没下到，
> 也照样显示 `ok`。现在只要应下的报表不全（且不是平台不提供 / 没数据），就是 `partial`。

备注列：

- **`N 张仍欠`**：报表已申请但还没取回，请求不会丢，下次 `--collect-only`
  （或窗口里的「补取欠的报表」）就能取。为什么没取到，看下面的原因表。
- **`N 张未下载`**：这一趟确定没拿到的报表，原因同样在下面。
- **`N 张无流水`**：所选时间段内没有任何流水，MercadoPago 不会生成这张表。
  **这不是错误。**

### 没下到的报表：为什么没下到

以前一轮跑完只留下 `尚未就绪`、`仍欠 2 张` 这样的话，没有原因。现在脚本先按参数
算出这一趟**应该**下到哪些报表，没到的每一张都给**一个原因码**，并在放弃的那一刻
把现场记下来。批次汇总后面紧跟一段：

```
未下载的报表与原因
  NARWAL_EE01 | mercadopago/release（5/jul/2026 a 2/sep/2026）
      原因    [STILL_GENERATING] 平台还在生成，尚未就绪：……
      责任方  平台 ｜ 重试有用
      下一步  稍后运行 run_batch.py --collect-only 补取
      证据    _diag/154233_mercadopago_release.json

  按原因统计：
    STILL_GENERATING           1  平台还在生成，尚未就绪
```

同一家店同一个原因的报表并成一行。应下的全部到齐时这一段只写「没有」。

| 原因码 | 意思 | 谁的问题 | 过会儿重试有用吗 | 你该做什么 |
|---|---|---|---|---|
| `STORE_OPEN_FAILED` | 店铺浏览器没打开，或中途断开 | 紫鸟 | 有 | 确认紫鸟客户端已登录、这家店能手动打开，再重跑这家店 |
| `LANGUAGE_WRONG` | 页面语言不是西班牙语，脚本按西语文字找不到控件 | 账号 | 没用 | 在这家店的浏览器里把账号语言改回 Español，再重跑 |
| `NO_PERMISSION` | 这个登录账号没有查看报表的权限 | 账号 | 没用 | 请账号管理员在 Colaboradores 里授予报表权限 |
| `PAGE_BLOCKED` | 打开的不是预期页面（登录、验证或错误页） | 账号 | 有 | 手动进店完成登录/验证，确认页面能正常打开后重跑 |
| `PLATFORM_ERROR` | 平台临时出错，返回的是 5xx 错误页 | 平台 | 有 | 过一会儿重跑这家店；持续出现就去平台状态页或手动打开页面确认 |
| `UI_NOT_FOUND` | 页面是对的，但要点的控件找不到或点不了 | 脚本 | 没用 | 把证据截图发给维护人：多半是平台改版，要改选择器 |
| `REQUEST_NOT_REGISTERED` | 点了生成，但平台的列表里没有这张报表 | 平台 | 有 | 重跑这家店重新申请；反复出现就在页面上手动生成一次 |
| `STILL_GENERATING` | 平台还在生成，尚未就绪 | 平台 | 有 | 稍后运行 `run_batch.py --collect-only` 补取 |
| `PLATFORM_DELAYED` | 平台提示数据还在处理，要等几个小时 | 平台 | 有 | 几小时后运行 `run_batch.py --collect-only` 补取 |
| `NO_DATA` | 该区间没有数据，平台不会生成报表 | 平台 | 没用 | **无需处理** |
| `NOT_AVAILABLE` | 平台不提供：账期还没开始 / 没有这一期 / 店铺没有 Full | 平台 | 没用 | **无需处理**；若认为应该有，对照证据核实 |
| `DOWNLOAD_NOT_LANDED` | 报表已就绪也点了下载，但文件没有落盘 | 紫鸟 | 有 | 重跑补取；反复出现就查磁盘空间、下载目录权限和浏览器的下载拦截 |
| `FILE_REJECTED` | 文件下到了但不能用（空文件，或已经不在目录里） | 平台 | 有 | 重新下载这张报表 |
| `INTERNAL_ERROR` | 脚本自身出错 | 脚本 | 有 | 把异常信息发给维护人；可以先重跑一次 |
| `EXPIRED` | 超过保留期仍没取回，已不再追踪 | 脚本 | 没用 | 还需要的话重新申请这张报表 |
| `UNKNOWN` | 现有证据分不清原因 | 脚本 | 有 | 打开证据文件和截图人工判断 |

`NO_DATA` 和 `NOT_AVAILABLE` 两种**缺了是对的**，不算"需要关注"，不影响店铺状态
和退出码。其余的都算。

**证据在哪**：`downloads/<店名>/<时间戳>/_diag/` 下，每张没下到的报表一份
`<时分秒>_<报表>.json`（当时的页面地址、标题、页面上可见的提示条、那一行的状态）
加一张同名 `.png` 截图。店铺根本没打开时没有截图，证据就是异常本身和紫鸟的原话。

**同一份结论还写在这几处**，按你手边有什么来看：

| 位置 | 内容 |
|---|---|
| `downloads/<店名>/<时间戳>/REPORT.md` | 「未下载 —— 原因」一张表：报表、期间、原因、重试有用否、下一步、证据。补收之后会更新 |
| `downloads/<店名>/<时间戳>/run_meta.json` | `expected`（应下的）、`missing`（缺的，带原因和证据）、`flags`、`cautions` |
| `logs/batch_<时间戳>.json` | 每家店的 `missing`，加上整批的 `missing_by_cause`、`stores_ok` / `stores_attention` / `stores_failed`、`cleaning` |
| `logs/pending.json` | 每条还欠着的报表：探测了几次、首末探测时间、最后看到的状态、证据、当前原因码 |
| `logs/pending_expired.json` | 超过 7 天被清掉的条目，原因码 `EXPIRED` |
| 告警文件 `！报表异常_<年月>.txt` | 按原因码统计的张数 |

> **「已下载但要留意」。** MercadoPago 有时点了生成之后列表里并不出现新的一行，
> 脚本只能按列表里**已有的**那一行去取。通常那就是当天早些时候申请的同一区间；
> 但也可能取回一张**更早**的报表。这不算失败，文件照常下载，但会在批次汇总和
> `REPORT.md` 的「留意：按列表里已有的行匹配」里记一笔，写明「申请」的区间和
> 「采用」的区间 —— 两者对不上时就要核对那份文件。

> **没有 Full 仓的店。** 库存那 5 张报表它本来就没有。把店名写进 `config.json` 的
> `stores.no_full`（或临时用 `--no-full-stores 店名`），缺的库存报表就记成
> `NOT_AVAILABLE` 而不是每次都提醒。脚本不会自己猜 —— 页面上"没有 Full"和
> "菜单没渲染出来"长得一样。

### 清洗跑完

下载完会自动跑一遍清洗，汇总里有一行：

| 结果 | 含义 |
|---|---|
| `成功` | 每个文件都洗进去了 |
| `部分文件失败，其余已写入` | 个别文件的结构对不上（平台改了导出版式，或文件本身坏了），**其余数据和 DuckDB 视图都是好的**。往上翻 `ERROR` 行看是哪个文件 |
| `失败` | 一个文件都没洗成，或者根本没匹配到任何报表类型 |

区分这两档很重要：55 个文件里坏 1 个和一个都没洗成，处理方式完全不同 ——
前者只需重下那一个文件，后者说明环境或路径出了问题。

**以前下载的旧文件洗不动，不再算这一轮的账。** 清洗每次都把整棵 `downloads` 树
重扫一遍，所以一个洗不动的旧文件会让之后每一轮都报「部分文件失败」、整批退出码 1
（2026-10-09 那轮 902 个文件里 28 个失败，全是 9 月的旧导出）。现在只有**这一轮下载目录里**的
文件失败才算数；旧文件只在后面列一段 `note: N file(s) from earlier runs still cannot
be cleaned`，结果仍是 `成功`。

那批文件洗不动的原因也修掉了：销售报表（Ventas）、账单（Facturación）和贷记单
（Notas de crédito）现在**按列名找表头行**，不再认死第几行。平台在导出顶部插一行
横幅（比如"数据不全"的提示）时整张表会下移一行，以前就会读错表头。

`ERROR ...: expected columns missing from export: [...]` 是最常见的一条，
意思是那份导出的表头跟预期对不上。**重新下载那家店对应的报表**通常就好了；
如果每家店都这样，那是平台改了导出版式，需要改代码。

### 财报跑完

```
  报表                     结果               用时  文件
  TANKE_EE               有校验未过           7s  TANKE_EE_2026-08.xlsx
  UNIT_PW01(catalog)     成功                1s  UNIT_PW01(catalog)_2026-08.xlsx
  BOCINA_TA02            写入失败             1s  —
```

| 结果 | 文件写出来了吗 | 含义 |
|---|---|---|
| `成功` | 是 | 全部校验通过 |
| `有校验未过` | 是 | 有 error 级校验没过，去 ⑩ 页看是哪条 |
| `公式错误` | 是 | 重算后文件里有公式报错 |
| `数据不全⚠` | 是 | 平台自己声明这份 Ventas 导出不完整，需重新下载核对 |
| `严格模式未写出` | **否** | 加了 `--strict`，有校验未过或 Ventas 数据不全，按要求不写 |
| `写入失败` | **否** | 文件没写成（多半被 Excel 占用），磁盘上还是旧版 |
| `生成出错` / `超时` / `未写出` | **否** | 生成过程崩了、超时，或其他原因没有产出文件 |
| `无可用数据` | **否** | 每家店的数据都用不了 |
| `跳过` | **否** | 根本没启动 |

没有可用下载目录的店铺单独列在表后的「未参与」里。

每条未通过的校验**只在那份报表自己的 `[校验]` 段里打印一次**，排查提示紧跟在它
下面；最后的汇总表里每份报表只再占一两行（`未过 N 项：…`、`提醒 N 项：…`，
后面括号里是涉及的店铺）。

只有报表**没写出来**时，才会把那次生成的完整输出存到 `logs/report_diag/`，汇总里
会打印路径（`完整输出已存：…`）。成功的报表不再留诊断文件。

| `4` | `config.json` 读不了，或店铺清单为空 |

**报表** `run_reports.py`

| 码 | 含义 |
|---|---|
| `0` | 要的报表全部写出，error 级校验全过，源数据没有被平台标为不完整 |
| `1` | 要的报表**全部写出**，但有要看一眼的：校验未过、公式错误、Ventas 数据不全，或只出汇总时汇总里缺了没有下载目录的店 |
| `2` | 至少一份要的报表**没有写出来**（报错、超时、`--strict` 中止、写入失败、某家店没有可用的下载目录），或没有任何一家店可用 |
| `3` | 店名不在白名单 |
| `4` | 配置错误 |

**运行器** `run_monthly.py`（窗口顶上横幅说的就是它）：以上 0–4，再加三个

| 码 | 含义 |
|---|---|
| `0` | 全部正常 |
| `1` | 跑完了，但有需要关注的项 —— 看日志里标黄标红的行，或报表的 ⑩ 页 |
| `2` | 没跑成：紫鸟客户端出错 / 没有一家店下到数据 / 有报表没生成 |
| `3` | 没跑成：店铺不在 `config.json` 的白名单里 |
| `4` | 没跑成：`config.json` 读不了或格式不对 |
| `5` | 没跑：另一轮还在跑，这次被跳过了 |
| `6` | 被人中止了 |
| `7` | 下载超过时限被掐断，报表是按已下到的数据出的 |

下载那步是 0 或 1 时照常出报表（缺的会体现在 ⑩ 页）；是 2 / 3 / 4 时不出。

## 10. 不是代码能解决的问题

**MercadoPago 报表权限。** 有些店的登录账号没有报表权限，页面显示
*"No tienes permisos para ver los reportes"*。脚本会明确报出来，但这需要
**账号管理员**在 MercadoPago 的「Colaboradores」里授予两项权限：
*Acceder a reportes de tus cobros y facturación* 和 *Acceder a reportes de operaciones*。
代码绕不过去。少了这个，该店就没有独立的现金凭证可做交叉验证。

**报表生成慢。** `Liberaciones` 这张表在多家店都出现过要几小时的情况。
脚本不会一直干等 —— 记进 `logs/pending.json`，之后补取。

**账单期数。** 平台的账单页面只显示最近 3 期。期数不够时桥B 会平不了账 ——
这不是代码问题，是数据不全。

**界面语言必须是西班牙语。** 整个下载层靠可见的西语文字定位元素
（`Ir al detalle`、`descargar`、`almacenamiento`…），导出文件的列名也是西语，
而**导出文件的语言跟着账号的界面语言走**。谁在浏览器里把语言改成 English 或
中文，下一轮跑批的报表就是错的。

脚本现在会挡：每家店进店后、跑任何路线之前，先读顶栏用户菜单里的
`data-selected-locale`，不是 `es_MX` 就**自动切回去**，并在批次汇总里记一笔
「界面语言原本是 en_US，已改回」。判据用的是 locale 代码不是可见文字 ——
用文字判断语言，语言一变判断自己就先瞎了。

> 为什么值得专门挡：元素找不到会抛错，看得见；但**账期页的月份名核对失败会
> 静默跳过整期**，报表少算费用而毫无提示。只漏一期账单就让 EWTTO_SM 少算佣金
> 973.23、代扣税率从 9.172% 虚高到 9.221%。

MercadoPago 那边没有语言切换器，只能读 `<html lang>` 并**警告**，改不了。
它多半跟着 MercadoLibre 的账号设置走，但这一点没有实测过。

## 11. 项目结构

> **文件放在哪：** 2026-10 起，各平台通用的模块在 `core/`（运行器、窗口、日志、紫鸟、
> 店铺配置、没下到的原因……），MercadoLibre 专用的在 `platforms/mercadolibre/`
> （下载路线、报表）。文件名没变。根目录只留双击入口、`config.json`、`downloads/`、
> `logs/`，以及 `run_monthly.py` / `list_stores.py` / `open_store.py` 三个转发文件，
> 老命令照样能用。完整目录见 `docs/ARCHITECTURE.md`。

## 12. 出问题先做这三步

1. `.venv\Scripts\python bootstrap.py` —— 环境是不是好的
2. `.venv\Scripts\python -m platforms.mercadolibre.run_batch --dry-run` —— 配置读出来对不对
3. **看那一轮的运行日志** —— 双击 `月度报表.cmd`，在右边「运行日志」的
   「看哪一轮」里挑出那一轮，级别选「警告和错误」。文件本身在
   `logs/runs/<开始时间>_<入口>.log`，同名 `.json` 里有每一步的退出码。
   先看第 2 列分清是手动跑的还是定时跑的（见
   [运行日志](#运行日志窗口右边那一栏)）。
4. 缺报表：看日志里「未下载的报表与原因」那一段，或 `logs/batch_<时间戳>.json`
   —— 哪家店、哪张报表、什么原因、证据在哪（见
   [第 9 节](#没下到的报表为什么没下到)）
5. 报表没写出来：看 `logs/report_diag/` 里那次生成的完整输出

窗口点了按钮却"没能启动"（一条日志都没有）：弹窗里会贴出错误输出，同一份内容存在
`logs/runs/_launch_manual.err`。

绝大多数"跑不起来"都是前两步能查出来的：Python 用错了、目录不对、
或者紫鸟客户端没装 / 没开 WebDriver 权限。

报表数字有疑问，按这个顺序查：

1. **⑩ 页** —— 哪条校验没过，明细写在那里
2. **③ 平账勾稽表** —— 五座桥，找出是哪一段对不上
3. **④ 平台费用明细** —— 具体是哪个科目
4. 还不行就翻 `downloads/<店名>/<时间戳>/` 里的原始报表
